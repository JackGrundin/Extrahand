# FastGig – App för flexibla jobb och uppdrag

## Vad appen gör
Plattform som kopplar samman företag och privatpersoner för kortare jobbpass och längre uppdrag. Företag publicerar jobb med datum, tider, adress, timlön och OB-tillägg. Privatpersoner ansöker, chattar med företag och får betyg efter avslutat pass. Det finns även en schemafunktion för längre uppdrag som sommarjobb och säsongsarbete.

## Viktiga detaljer
- Alla fält i jobbformuläret är obligatoriska utom OB-tillägg (titel, beskrivning, kategori, stad, adress, timlön, antal dagar, datum+tider per dag). Delad validering i frontend/src/utils/jobbValidering.js (valideraJobb) + inline-fel via components/FältFel.js. Backend är sista försvaret: routes/jobb.js valideraJobbInput körs i både POST och PUT och avvisar bl.a. tom/0 timlön med 400 – annars ger jobbet en tidrapport på 0 kr
- ADMIN-VY: info@fastgig.se har flikar på webben: Dashboard, Tidrapporter, Avtal, Företag, Privatpersoner, Fakturering, Raderade konton. Admin kan godkänna/återkalla avtal och skickar ett mejl med orsak vid återkallande. Raderade konton-fliken visar inaktiva konton (aktiv = false) med möjlighet att återkalla kvarvarande avtal. Tidsfilter (denna månad / senaste 3 månader / senaste 6 månader / detta år / totalt) styr Ekonomi- och Aktivitetskorten på dashboarden samt hela tidrapport- och faktureringsvyerna – filtrerar på tidrapport.datum. Användar-räknarna på dashboarden (Totalt användare, Företag, Privatpersoner, Pro) är alltid totaler och påverkas inte av filtret. Delad localStorage-nyckel för filtervalet så att valt period följer med mellan admin-sidorna
- FAKTURERINGFORMEL (via Invoicery Business): fakturapris = bruttolön × BRUTTO_KOEFFICIENT × (1 + påslag), där BRUTTO_KOEFFICIENT = 1.3142 / 0.94 ≈ 1.3981. Kedjan: fakturabelopp − Invoicery 6% − sociala avgifter 31,42% = bruttolön; − skatt 30% = nettolön. Konstanten bor i backend/utils/pris.js och speglas i frontend/src/utils/konstanter.js och web/src/utils/konstanter.js – ändra alltid på alla tre ställena
- OB-fakturering: samma formel med ob_belopp i stället för timlön
- Påslaget är 0.20 (Pro-kunder + gratiskontonas två första pass per månad) eller 0.40 (från 3:e passet), 0.15 för scheman och inbjudan enstaka pass, 0.07 för inbjudan schema. Formeln bor i backend/utils/pris.js och speglas i frontend/src/utils/konstanter.js och web/src/utils/konstanter.js – ändra alltid på alla tre ställena
- Påslaget FRYSES på jobbet (Jobb.paslag) när en ansökan GODKÄNNS – inte vid publicering – och kopieras sedan till tidrapporten. Tas godkännandet tillbaka nollas påslaget och räknaren minskas: ett pass som aldrig blev av ska inte kosta något. Jobb utan påslag faktureras med 40%
- Två skilda storheter: pass_denna_manad räknar GENOMFÖRDA (godkända) pass och styr påslaget, medan popupen vid publicering styrs av antalet jobb företaget publicerat denna månad (räknas direkt ur Jobb, ingen kolumn – så ett borttaget jobb försvinner automatiskt ur räkningen)
- Planvals-popupen visas högst EN gång per månad. Väljer företaget "Fortsätt utan abonnemang" stämplas planval_manad ('YYYY-MM') och de slipper frågan resten av månaden. Stämpeln är självläkande: avser den en tidigare månad räknas valet som ogjort, så popupen kommer tillbaka vid månadsskifte utan cron
- Ett jobb = ett pass och räknas EN gång. Godkännandevägen är inte idempotent (företaget kan godkänna, återkalla, byta person), så räkningen villkoras på om jobbet redan hade en godkänd ansökan – se hämtaGodkändaFörJobb i routes/ansokningar.js
- Prenumeration: Pro 299 kr/mån via Stripe Checkout (extern webbläsare) + Stripes kundportal. Webhook på /webhooks/stripe måste monteras med express.raw FÖRE express.json, annars går signaturverifieringen inte att göra

Ansökan fryser JOBBETS kravlista i ansokningar.intygade_krav (+ intygat_at), aldrig den lista klienten skickade – klientens lista används bara för att kontrollera att allt kryssats i. intygade_krav är nullbar UTAN default och skillnaden bär: NULL = ansökan från före funktionen fanns, [] = jobbet hade inga krav. Reglerna bor i backend/utils/behorighet.js (normaliseraKrav, valideraBehorighetsKrav, saknadeKrav) och speglas av frontend/src/utils/behorighet.js – ändra alltid på båda ställena

- Auto-tidrapport (cron/schemaTidrapport.js, var 5:e min) och påminnelse dagen före (cron/schemaPaminnelse.js, var 15:e min) är idempotenta via DATABASEN: krävPassFörRapport flyttar schema_pass planerad→rapporterad och krävPåminnelse stämplar paminnelse_skickad_at, båda i villkorade updates
- Schemapass rapporteras med SCHEMALAGDA timmar (brutto, ingen rast). Vid övertid eller rast rättar företaget rapporten via PATCH /api/tidrapporter/:id/korrigera, så länge den är auto_skapad och fortfarande 'väntar'
- AVHOPP: syns bara via ansokningar.avhoppad_at (nullbar timestamptz). Statusen förblir 'avvisad'. Stämpeln sätts på EXAKT ett ställe: POST /scheman/:id/hoppa-av, via markeraAvhopp i db/ansokningar.js. återställSchema anropas också när FÖRETAGET tar tillbaka ett godkännande – det är inget avhopp, stämpla aldrig där. MinaAnsokningarScreen filtrerar bort pass-ansökningar (schemaPassId != null)
- BETYGSPROMPTEN (BetygsContext, monterad i App.js): POST /api/betyg har INGEN kräverTyp. Underlaget är GET /api/betyg/vantande → hämtaObetygsatta i db/betyg.js, som grupperar på schema_id + motpart – ett schema med 14 pass ger annars 14 prompter för samma person. En grupp räknas som klar om NÅGON ansökan i den har ett betyg från mig. "Hoppa över" sparas bara lokalt i AsyncStorage ('fastgig.betyg.hoppadeOver'). Dubbletter spärras av ett unikt index på (ansokan_id, av_anvandare_id)
- Tider tolkas alltid som svensk lokaltid via backend/utils/tid.js (delad av alla tre cron-jobben). Använd hourCycle 'h23' i Intl – med hour12:false svarar vissa ICU-versioner timme "24" och ger ett dygns fel i offseten
- Prenumerationssystem: gratis (2 pass/mån med lågt påslag, sedan högre påslag), Pro 299 kr/mån (alltid lågt påslag). Stripe hanterar betalning och prenumerationshantering

## Tech stack
- Backend: Node.js med Express, REST API
- Databas: PostgreSQL via Supabase
- Frontend: React Native med Expo (mobilapp)
- Webbapp: Next.js 14 (App Router), Vercel (fastgig.se)
- Auth: JWT-tokens (eget system med bcrypt)
- Hosting: Railway (backend via api.fastgig.se), Supabase (databas)
- Mejl: Resend (noreply@fastgig.se)
- Realtid: Supabase Broadcast
- Betalning: Stripe (prenumerationer)

## Kodstil
- Använd async/await, inte callbacks
- Kommentera på svenska
- Varje fil ska ha tydliga funktionsnamn
- Felhantering på alla API-endpoints
